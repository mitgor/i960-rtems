# AcceleRAID 160 RTEMS-sized transfer scale proof

Status, 2026-10-17: **77-page contiguous upload and whole-image digest accepted.** This is a deterministic transfer test under the persistent owned-execution firmware, not a ported RTEMS image. The old DAC960PG `37:04.1` stayed unbound.

The [bounded runner](../../../host/accele160/bulkupload/run_bulk.py) pins exact firmware SHA-256 `6f056a984d8e8d6fde6eb2001bddfd5ecc3b03918051c4d13e3cc4ab31480aa7`, exact reserve/copy/digest/release modules, the explicit new-card BDF, old-card-unbound state and two same-boot guarded full-flash reads. It reserves one stock-owned 512 KiB grant at `c0710000`, stages and reads back each deterministic 4 KiB page through `c078f000`, reloads the one-shot copy companion between pages, verifies each card-reported FNV and unchanged loader/allocator state, then asks operation 7 to digest the contiguous image. It restores staging, controls, loader page, PIATVR and all 512 allocator owner/count words before freeing the grant. Any uncertain command retains resources for inspection.

The [live capture](live/bulk-77/) copied **77 × 4,096 = 315,392 bytes** (284 bytes more than the archived DAC960PG IPv6 RTEMS flat image of 315,108 bytes). All 77 page commands returned status/residual zero and agreed with the host's per-page data. Total upload wall time was **6.118 s**, or **51,554 B/s** including 77 one-shot module cycles, staging MMIO, validation and audits. Copy-command completion observations were 50.636–51.099 ms (median 50.956 ms), summing to 3.923 s; other host/module work accounted for about 2.195 s. The card's whole-region FNV was `0x11a9edc5` and the digest command took **0.101 s** as observed by the host. These timings are one run, not throughput guarantees.

The one 512 KiB grant has 127 payload pages and one 4 KiB staging page, so 77 pages leave **50 payload pages = 204,800 bytes** for additional image extent, BSS, stacks and heap. The archived old-board image size alone does not prove that its RTEMS workspace or network buffers fit this new-board layout. It also contains old-board addresses and transport assumptions and was not executed here.

[Independent replay](../../../host/accele160/bulkupload/verify_live.py) checked all 77 concatenated staging readbacks, all 77 copied-page result/loader snapshots, 77 command statuses, the full-image digest, and reserve/release metadata. It passed; mutations to a middle staging page, last copy report, digest, one command status and owner metadata were rejected. The [post-test guarded full-flash read](live/postbulk-flash/result.json) matched exact firmware with zero status/residual/DMA guard changes. No command companion remained loaded.

The next useful step is a pinned arbitrary-image upload manifest and a newly linked AcceleRAID RTEMS payload with explicit load address, BSS/stack/heap extent, entry and bounded STOP contract. Start with a small task/clock image; add networking only after that lifecycle passes. Doom still requires a separately proven 8 MiB arena.
