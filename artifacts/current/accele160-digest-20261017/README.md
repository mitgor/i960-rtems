# AcceleRAID 160 owned-image digest candidate

Status, 2026-10-17: **persistent operation 7 and the bounded two-page digest accepted.** The PC returned after reboot on boot `35e4d4b0-ed11-42ff-a5fb-e5f8f2fb2f2c`; two guarded 1 MiB reads matched the exact candidate before any live command. The old DAC960PG `37:04.1` remained unbound throughout.

The exact [1 MiB candidate](candidate.bin) has SHA-256 `665cb1210ed92b373b43d1a126cc547860cd58c0e95a9905f26f697005c708a0`. It extends the accepted page-copy image `183eed37…d197f4a` with operation 7. The 1,808-byte [handler](../../../host/accele160/digest/handler.S) has SHA-256 `77818785ae84fc9269c90d890091d45d1fe12b68d8845505558d1c0e2b7c55f6`, no ELF relocations, and uses the existing loader cave. The exact-image [audit](../../../host/accele160/digest/audit.py) permits only handler-cave and two checksum-word changes; 1,487 bytes differ. Expanded runtime and boot block are unchanged. Offline mutation tests pass.

Operation 7 accepts the existing zero-DMA `0x8f` mailbox envelope with fixed nonce `0x16161071`. A separate 16-byte host-written control at `c000f870` contains `HASH`, the same nonce, page count 1–127, and expected FNV-1a. The card verifies the retained 512 KiB owner record and grant range, invalidates D-cache, hashes exactly the requested contiguous pages starting at the grant base, and returns `HASH`, nonce, page count and digest at `c000f830` only if the digest matches. A bad count or digest returns stock unsupported status. FNV detects transfer errors; it is not a cryptographic authenticity check. The host still pins exact firmware/module hashes.

Before programming, a guarded 1 MiB `READIMAGE` matched the prior candidate, and `STOREIMAGE` plus independent guarded 1 MiB `READIMAGE` matched this candidate. One `FLASHIMAGE` completed in 37.024 seconds with status/residual zero. The old DAC960PG `37:04.1` stayed unbound. Full data reads remain on the test PC; [compact receipts](live/) are archived here.

The accepted [host harness](../../../host/accele160/digest/run_digest.py) is limited to two deterministic contiguous pages. It requires two same-boot full-flash reads, checks card identity, owner metadata and both page-copy checksums, then requests the card-computed digest over all 8 KiB. It restores staging, control/result slots, loader page and allocator ownership before unloading companions. [Replay verifier](../../../host/accele160/digest/verify_live.py) passed on the live captures, and six deliberate mutations to staging, copy results, digest result, unrelated loader bytes and metadata were rejected. No RTEMS or Doom code is called by this operation.

## Live acceptance and rejection

On the post-reboot boot, [persistent read 0](live/persistent-0/result.json) and [read 1](live/persistent-1/result.json) independently returned the exact candidate SHA, with status/residual/DMA guard changes zero. New card `37:09.1` was explicitly bound to `myrsread`, and old `37:04.1` was unbound.

The [live session](live/digest-live/) reserved the fixed 512 KiB stock grant at `c0710000`, copied deterministic pages 0 and 1 through the validated odd staging page, then operation 7 hashed the contiguous 8 KiB from grant base. Host and card FNV-1a both were `0x3201b5c5`; command status and residual were zero. The host separately read back odd page 1, restored staging, controls and loader page, released the grant, and verified all 512 allocator count/owner words returned to their preimage. All companions unloaded and PIATVR returned to `c0000000`. A guarded [post-call full flash read](live/postcall-flash/result.json) still matched the candidate.

The [negative harness](../../../host/accele160/digest/run_digest_negative.py) repeated the two-page preparation under a fresh grant for each rejection. [Wrong expected hash](live/digest-bad-hash/) and [page count 128](live/digest-bad-count/) both returned stock unsupported status 2, left the result sentinel intact, and left independently readable odd page 1 unchanged. Both sessions restored staging, controls, loader page, allocator metadata and PIATVR, and unloaded companions. [Negative replay](../../../host/accele160/digest/verify_negative.py) passed; four deliberate mutations to the result, control, target and owner metadata were rejected. A final [guarded 1 MiB read](live/post-negative-flash/result.json) still matched exact flash with unchanged DMA guards.

This is a whole-image **transfer** digest over a small contiguous uploaded image. FNV is not a cryptographic signature. It does not prove an executable cache handoff, a normally returning call from the grant, longer-lived task ownership, RTEMS or Doom. The next gate is a fixed, tiny, normally returning payload under the same owner and digest checks, with an explicit instruction-cache invalidate and full restoration.
