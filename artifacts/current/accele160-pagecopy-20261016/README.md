# AcceleRAID 160 bounded card-side page-copy experiment

Status, 2026-10-17: **persistent flash, indexed page copies and two rejection paths passed.** The PC returned after reboot; two guarded full-image reads matched before operation 6. The old DAC960PG `0000:37:04.1` remained unbound and untouched through preflash, stage, readback and flash.

The 1 MiB [candidate](candidate.bin) SHA-256 is `183eed37b6a3764961e8f66fc9bda73ed7ed3547a7686bf605bcb2b6cd197f4a`; its 1,512-byte [handler](../../../host/accele160/pagecopy/handler.S) SHA-256 is `d4fb53c0…daad537`. It preserves the accepted PING, 80-byte RAM-call, transient allocator and retained 512 KiB grant operations. It adds operation 6, and changes operation 5 to invalidate D-cache before freeing an allocation after the host has restored its staging page. The image changes 1,231 bytes relative to the accepted retained image `e7a3a7c5…d6ffc0`, confined to the loader cave and two checksum words. Expanded runtime and boot block remain byte-identical. The assembler output has no relocations, and [offline audit tests](../../../host/accele160/pagecopy/test_audit.py) pin the exact image and reject mutated inputs.

Operation 6 keeps the 64-byte mailbox zero-DMA except for its fixed operation, signature and nonce. A separate 16-byte host-written control record at `c000f860` contains `COPY`, the matching nonce, target page index `0..126`, and expected FNV-1a of the 4 KiB staging page. The handler checks the retained owner record and grant range, invalidates D-cache before reading PCI-written bytes, rejects a bad staging hash before copying, copies exactly 4 KiB from the final odd grant page (`grant + 0x7f000`) to an indexed destination, hashes the destination and reports it at `c000f820`. Index 127, the staging page itself, is excluded. The first host experiment fixes the target index to 0, an even page inaccessible directly through BAR0. FNV is a transfer-error check for this bounded proof, not a cryptographic image admission digest.

On boot `9839abdc-1540-4638-af18-ff8b76bc7e5d`, guarded preflash 1 MiB `READIMAGE` matched the accepted retained image. `STOREIMAGE` staged the new candidate; independent 1 MiB `READIMAGE` matched its SHA with zero status, residual and DMA guard changes. One `FLASHIMAGE` completed in 37.013 seconds with status/residual zero. [Compact receipts](live/) preserve those commands. The redundant full data files remain at `/home/mit/i960-accele160-pagecopy-20261016/` on the PC. Post-boot persistence was separately established on boot `17306017-d86c-45a9-9849-d6f18d448b36` by two full selector-9 reads with exact candidate SHA, status/residual/guard changes zero.

On that boot, exact `myrsread` binding on `37:09.1`, old card unbound, PIATVR `c0000000`, and two independent same-boot guarded full-flash reads matched the candidate. The [host session](../../../host/accele160/pagecopy/pagecopy_session.c) then reserves 512 KiB; checks all allocator count/owner words; writes and reads back 4 KiB in the last odd grant page; submits only the bounded copy command; verifies card-computed destination FNV; restores the control/result/staging page; and releases the grant. Any uncertain command or audit retains the modules and allocation. [Replay and tamper tests](../../../host/accele160/pagecopy/verify_live.py) pass. This is a first even-page copy proof, not a whole RTEMS image upload or code-execution proof.

## Live copy and audit

The [bounded session](live/pagecopy-0/) reserved the fixed 512 KiB grant at `c0710000`; its final odd page `c078f000` held a deterministic 4,096-byte pattern. Host MMIO readback matched all bytes. Operation 6 used target index 0 and returned status/residual zero with destination FNV-1a `0x6121fdc5`, matching the host-computed value. Disassembly shows the handler validates the staged hash before its 1,024-word copy loop and hashes the destination afterward. The result and 16-byte control record were restored; the staging page was restored byte-for-byte; then the separate release command returned status/residual zero. Exactly 16 blocks had owner `0x96016004` during the grant and all 512 allocator count/owner words returned to the preimage. All three companions unloaded, PIATVR returned to `c0000000`, and the old card remained unbound.

A guarded post-call full-flash read matched the candidate with unchanged DMA guards. An independent loader-page snapshot and two independent allocator-table snapshots matched their pre-call data. [Live replay](live/pagecopy-0/replay.json) passed; deliberate changes to staging readback, result FNV, control index, owner metadata and unrelated loader bytes were rejected. The full 1 MiB readbacks remain on the host; compact receipts and 4 KiB captures are archived here.

This proves bounded card-side copies to sampled even and odd pages, plus rejection of two invalid controls. It does **not** prove every target index, whole-image admission, executable cache handoff, task lifetime or RTEMS. The next upload milestone is a whole-image digest before a normally returning code proof. The 512 KiB grant reserves the final 4 KiB page for staging, leaving 520,192 bytes for payload. Doom still requires a separate 8 MiB ownership design.

## Additional same-boot acceptance (2026-10-17)

With the same persistently flashed candidate and paired guarded full-image reads, [index 1](live/pagecopy-index1/) copied to directly readable odd page `c0711000`; the independent host readback matched every byte and card/host FNV was `0x39fc55c5`. [Index 126](live/pagecopy-index126/) copied to the last allowed payload page `c078e000`; card/host FNV was `0x335cddc5`. Each run used a fresh 512 KiB grant and checked all owner/count words, staging restoration, loader page, companion release and PIATVR. These are sampled endpoints, not exhaustive coverage of all 127 indexes.

[Bad staged hash](live/pagecopy-bad-hash/) returned stock unsupported status 2 before copy; the independently readable index-1 destination was unchanged. [Forbidden index 127](live/pagecopy-bad-index-fixed/) likewise returned status 2, left the result sentinel intact and made no copy. Both successful rejection sessions restored staging, controls, loader page, allocator metadata and PIATVR and released all companions. [Offline replay](../../../host/accele160/pagecopy/verify_rejection.py) accepts both captures and rejects tampered target, result, index and owner metadata. Four page-copy audit/replay unit tests pass.

An initial bad-index **host checker** compared index 127's staging page to its pre-upload contents before restoring it. The card had already correctly returned status 2. The checker stopped and retained the grant, as designed. [Captured failure state](live/pagecopy-bad-index/) and the [guarded cleanup](../../../host/accele160/pagecopy/cleanup_rejected.py) show exact checks of the card page, staging and owner table before restoration. The release command completed asynchronously; [final cleanup](../../../host/accele160/pagecopy/finish_rejected_release.py) verified free result, full owner-table restoration, original stage and loader page, then unloaded the companions. The corrected checker skips the misleading comparison and the fixed bad-index run passed. No firmware change occurred during these additional tests.

A final [guarded full-flash read](live/post-negative-flash/result.json) after all copies and rejection tests matched the 1 MiB candidate SHA-256 `183eed37b6a3764961e8f66fc9bda73ed7ed3547a7686bf605bcb2b6cd197f4a`; status, residual and DMA-guard changes were zero. The complete readback stays on the test PC. Old `37:04.1` remained unbound.
