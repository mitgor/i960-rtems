# AcceleRAID 160 retained 512 KiB grant experiment

Status, 2026-10-16: **persistent flash and the fixed 512 KiB reserve/release proof passed on the new card.** The PC returned after reboot; two guarded full-image reads matched before any operation 4 or 5 command. The old DAC960PG `0000:37:04.1` has remained unbound and untouched.

The [handler](../../../host/accele160/retained/handler.S) preserves the accepted PING, fixed 80-byte RAM-call and 256 KiB allocate/free operations. New operation 4 requests one fixed 512 KiB stock mode-1 allocation with owner ID `0x96016004`, checks its expected pool and alignment, records the returned pointer at card-local `c000f840..f84f`, and reports it at `c000f820`. Operation 5 accepts only that saved record, frees its pointer through the stock route with the same size and owner ID, clears the record, and reports the release. Neither command dereferences a host-supplied pointer, size or DMA descriptor. The record is a card-local ownership marker, not yet an RTEMS loader.

The 1 MiB [candidate](candidate.bin) SHA-256 is `e7a3a7c5b4dcbbd933813155f03544cc691dac7e7b63fade79255d2452d6ffc0`; its 1,108-byte handler SHA-256 is `f134acc1…d83572c`. It changes 958 bytes relative to the accepted transient-allocator image `0124657d…799dd5d0`, confined to the loader cave and two checksum words. The expanded runtime and boot block remain identical. `readelf -r` found no relocations. [Offline image audit](../../../host/accele160/retained/audit.py) pins exact binary inputs/output, and tests reject mutations. The [replay checker](../../../host/accele160/retained/verify_live.py) models the 16-block owner transition and rejects tampered result/record/table bytes; the live capture passes.

On boot `0796a44a-14be-4487-b22d-5191a1946e16`, exact-BDF `myrsread` owned the new card and the old card was unbound. Guarded preflash `READIMAGE` matched the accepted transient-allocator image. `STOREIMAGE` staged the retained candidate and a separate 1 MiB readback matched it with zero status, residual and guard changes. One `FLASHIMAGE` completed in 37.104 seconds with status/residual zero. [Compact receipts](live/) preserve the preflash, stage, readback and flash facts; the redundant full image reads remain under `/home/mit/i960-accele160-retained-20261016/` on the PC. Post-boot persistence was separately established on boot `9839abdc-1540-4638-af18-ff8b76bc7e5d` by two full reads with exact candidate SHA, status/residual/guard changes zero.

The exact Linux `6.8.0-138-generic` [reserve](reserve_command.ko) and [release](release_command.ko) companions and [session executable](retained_session) are archived with [source](../../../host/accele160/retained/). The host session requires a fully erased loader result page and two same-boot exact flash audits. It snapshots all 256 count/owner words before, during and after the grant; verifies exactly 16 previously free blocks move to count 16 and owner `0x96016004`; restores the 16-byte result slot; then releases the grant and verifies both allocator metadata and the full loader page restore. A timeout or mismatch deliberately retains both command modules and the RAM grant. No upload or code execution is part of this test.

The accepted reserve/release proof supports a later upload into a retained grant; it does not prove cache-coherent execution or RTEMS. The stock mode-1 pool has at most 1,540,096 contiguous free bytes in the observed state; a 512 KiB RTEMS staging grant is plausible, while the 8 MiB Doom arena still requires a separate exclusive-memory design.

## Live grant result

The [bounded round trip](live/grant-roundtrip-0/) returned pointer `c0710000`, size 524,288 bytes, across exactly 16 previously free 32 KiB blocks. During the grant, each corresponding count word was 16 and each owner word was `0x96016004`; every other allocator count/owner word was unchanged. The release command restored all 512 allocator words to SHA-256 `8b49e75e…398c8b5f`; result and owner-record slots restored to the erased loader-page preimage. Both command status/residual pairs were zero, both modules unloaded, PIATVR returned to `c0000000`, and the old card remained unbound. The independent offline replay passes, with deliberately changed owner/result bytes rejected. A post-call guarded full-flash read still matched the candidate; a later loader-page snapshot matched the preimage byte for byte; two later read-only table snapshots retained the same count/owner SHA. Full 1 MiB readbacks remain on the host; compact receipts and 4 KiB captures are in git.

This proves a transient **retained** grant across two host commands. It does not prove data upload or execution. The PCI BAR0 upper 4 KiB maps `PIATVR + 0x1000` while PIATVR is 8 KiB aligned, so the host can directly access only every other 4 KiB page of this grant. A general RTEMS image needs a card-side bounded copy or a separately proven DMA path to populate the intervening pages. An owned-page write/read/restore experiment is the next gate.

## Owned-page transport proof

A second same-boot [session](live/owned-page-0/) reserved the same `c0710000` grant and selected its first accessible odd page, `c0711000`, through PIATVR `c0710000`. It wrote a deterministic 4,096-byte pattern, read every byte back, restored all 4,096 original bytes, and only then released the grant. [Offline replay](../../../host/accele160/retained/verify_owned_page.py) confirmed the pattern, readback, restoration, 16-block owner transition and exact result records; mutation tests reject changed pattern/readback bytes. The reserve and release commands returned status/residual zero; both modules unloaded and PIATVR restored. A further guarded full-flash read matched the retained candidate with unchanged DMA guards; independent loader-page and two allocator-table snapshots matched the pre-session page and metadata. This proves a reversible host write to **one owned odd page**. It does not prove that the i960 sees host-written code through its caches, nor does it expose the even pages.

The next firmware helper should reserve the final odd page of the grant as a 4 KiB staging window. For each page of an image, the host can write and read back that window, then request a card-side bounded copy into an indexed target page. The helper must validate its owner record, page index, chunk length and checksum before copying; read back a card-computed checksum afterward. Index 127 is the staging page, leaving 127 payload pages (520,192 bytes) in the 512 KiB grant. A whole-image digest and a normally returning code proof must precede a new RTEMS BSP. Keep the zero-DMA command envelope; put per-chunk metadata in a separately bounded loader control record so the stock mailbox sees no nonzero DMA descriptor fields. [Upload protocol design](../../../docs/hardware/accele160-upload-plan.md) records the detailed gates.
