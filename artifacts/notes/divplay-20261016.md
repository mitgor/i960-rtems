# Exact FixedDiv in play builds — physical acceptance

The new build path permits `--fast-fixed-div` without `--fixed-div-profile`.
It retains the previously tested exact C/assembly arithmetic, original signed
fallback and public `FixedDiv` ABI. The 47 call sites stay unchanged. Divide
profiling, timer reads, telemetry and 32 differential tests per frame are absent.
Frame, renderer CPU and WAD instrumentation remain enabled for this comparison.
All ownership, full paired audits and strict unused frame padding checks remain.

The [predeclared plan](PLAN.md) completed on the physical DAC960PG. The exact
divide remains opt-in. The four runs used unchanged A/B binaries in A1/B1/B2/A2
order, 520 frames each. Frames 100–499 supply 800 measured frames / 798 intervals
per implementation; no outliers were removed.

FPS improves **3.01%**; rendering finishes **4.325 ms sooner (3.06%)**.
The two candidate runs are 6.41256 and 6.41044 FPS. Individual baseline results
and all 100-frame subwindows are in `timing.json`; `comparison.json` pools
intervals correctly. CPU attribution uses 10 ms samples, not cycle counters.
BSP includes wall work, so this does not isolate traversal from wall drawing.
There is no demonstrated transport improvement: DMA-start-to-HTTP clock bounds
are 15.49–45.77 ms versus 15.10–44.82 ms and overlap. Neither measure is
input-to-browser-paint latency. HTTP observation is a binary receiver, not a
browser compositor benchmark. This comparison removes **divide** instrumentation;
frame/CPU/WAD counters and full audits remain. The previous profiled batch is a
separate experiment and must not be used as the matched baseline here.

## Correctness and lifecycle

- All **2,080 corresponding pixel/palette images agree**, including the menu.
  First 52 frames retain exactly the four known target/native differences at
  offsets 29260, 29261, 29580 and 29581. Both native builds pass the interactive
  40-frame test and two deterministic 52-frame runs with STOP/heap drain.
- **230 full paired audits** pass (58/57/57/58). Each run holds frames 17/18
  for about three seconds unchanged, then exercises held-frame STOP and heap
  cleanup. Maximum IRQ gap is **10.792 ms**. Full system/frame/WAD replay passes.
- Each run rejects all 24 frame mutations and four drain mutations. All **1,952**
  observed binary HTTP payloads match their captured frame exactly; this is not
  a claim that the receiver observed all 2,080 frames.
- The 1,120,252-pair host arithmetic test passes. The candidate C and assembly
  objects are byte-identical to the previous experiment with 66,560 on-card
  differential checks. This batch deliberately runs no per-frame differential
  tests; exact whole-frame comparison provides the on-card integration check.
- No divide profiler/check/record symbols occur in either linked engine. All
  2,080 reserved divide-telemetry tails are zero. Synthetic decoding rejects a
  nonzero reserved tail even when the fast arithmetic flag is enabled.
- Protected `R_PointOnSide` O0 object SHA remains
  `beb7a66306aef9fa8a0cb4c0e18e81524b337c05f640897282c3f8bedcc6dd1b`.
  Engine memory is 818,992 → 819,184 bytes; file/template is 434,824 → 435,016.
  The added 192 bytes require no new heap allocation. See `sizing-and-arithmetic.txt`.
  No ownership, audit, DMA or firmware changes were made.

The historical asynchronous menu discrepancy remains unexplained: this strict
pass does not replace frame/tic input-consumption tracing. Broader scenes and
high detail still need qualification. Keep this exact optimization optional.

## Reproduction

`build.sh build` and `build.sh build-fast` create the two matched builds in
`/home/mit/i960-divplay-20261016`. `native.py --baseline` and `native.py` each
exercise two identical 52-frame native runs. `accept.py` runs A1/B1/B2/A2,
replays and tamper-tests captures, saves and hash-checks evidence before reboot.
Only start after the current card owner releases it; never force-unload retained
exclusive resources. `check_frames.py`, `measure.py`, `compare.py` and
`summarize.py` report images, timing and lifecycle/audit results.
`check_unprofiled.py` verifies metadata, linked symbols and zero reserved tails.

## Build flags

For a fresh play build using the exact divide without divide instrumentation:

```sh
python3 game/doom/play/build.py --work /home/mit/doom-fast-div-play \
  --pipeline --pingpong --wad-ring --wad-profile --peer-yield \
  --frame-profile --cpu-profile --low-detail --no-fnv --direct-frame \
  --fast-render --fast-columns --fast-fixed-div
```

Add `--fixed-div-profile` when collecting call-site costs and running the bounded
arithmetic self-tests. Omit `--fast-fixed-div` for the original divide. Both
switches are off by default. This experiment keeps fixed low detail; runtime
detail switching remains a separate previously tested option.
