## Implementation and boundaries

The opt-in `--play-bulk` / wrapper `--bulk` path adds upload ioctl operation 11.
It retains the 1 KiB result size and all session, epoch, generation, offset,
length, unused-field and ownership gates. It selects the same immutable frame
and aligned window, then reads 128 eight-byte beats with opcode `0x6f`.

The target reads the second word into the already-owned IMR0 after consuming
its zero request. OMR0 carries the first word; cleared IMR1 and tagged OMR1
complete the existing handshake. The kernel session mutex protects both reads.
The target performs two bounded word loads per service invocation, without a
copy loop or a new address supplied by the host. Each beat permits 16 extra
poll iterations before the original sleep fallback; the absolute deadline,
20,000-iteration bound, mask/doorbell checks and uncertainty retention remain.
This is a **PIO mailbox bulk path with eight-byte beats**, not RAM-aperture
mapping or host-memory DMA. Low BAR RAM remains unreserved firmware state.

A frame and first-window reread cost 8,450 exchanges, 49.61% fewer. Both readers
now also check the live frame generation after the complete read, before ACK.
Every frame still includes 64,000 pixel bytes, 768 palette bytes and all zero
padding. The renderer remains parked until ACK; STOP and image pins are intact.
The full paired monitor/RAM audits keep their normal 60-second interval.

## Elapsed-time replay correction

The existing replay required one/two timer wraps whenever the **configured
maximum** session budget exceeded 180,000/210,000 ticks. A completed 28-frame
run can stop well before that ceiling. The coverage condition now uses the
final audited elapsed tick count. All snapshot, RAM, clock consistency and
allocation checks remain; runs actually exceeding those durations still must
show the same wrap and preemption evidence. `test_replay_duration.py` executes
the actual verifier gates and checks both legitimate short completion and
refusal of missing evidence at the thresholds.
