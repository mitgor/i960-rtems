# Exact FixedDiv profiling and bounded i960 divide

This experiment follows the fixed-column/span build. It preserves the selected
low-detail renderer, full paired system audits, DMA ownership checks, priority
frame release, WAD ring, stalled-host test, held-frame STOP and heap drain.
Firmware flash is untouched.

## Implementation and arithmetic contract

`--fixed-div-profile` identifies all 47 source call sites and measures each call
with the exclusive owner's existing timer-0 downcounter. It emits count/tick
pairs in a strictly checked FDV1 trailer. `--fast-fixed-div` additionally selects
the candidate and currently requires profiling. Both are opt-in.

Inspection of the actual linked `___divdi3` shows a general normalization and
quotient-correction path, using multiple `divo`/`remo` operations. It is not a
floating-point routine. The replacement preserves the saturation guard, forms
unsigned magnitudes, performs one `ediv`, then restores the sign. The guard
proves the divisor is nonzero and the unsigned quotient is below 2^30, so the
hardware divide cannot overflow. `INT_MIN` inputs retain the original compiled
implementation; the original `INT_MIN/0` reaches undefined division by zero
and is deliberately excluded from executable tests. There is no approximate
reciprocal and no gameplay arithmetic tolerance.

`game/doom/fixed_div/test.py` passes 1,120,252 host cases, including randomized
values, signs, zero, INT_MIN fallback and targeted saturation boundaries.
The i960 helper itself is tested on the card: both builds execute 32 bounded
comparisons against the original implementation before each display. A mismatch
terminates through the owned engine's fatal path. Native and target tests serve
different purposes; the host does not emulate the i960 instruction.

## Measurement scope

A/B/B/A, 520 frames per run, same scripted input and fixed low detail.
Frames 100–499 are the declared window: 400 frames / 399 intervals per run,
800 frames / 798 intervals per implementation. No slow intervals are removed.

**Both builds include profiling and differential-test overhead.** These FPS
numbers must not be compared directly with the previous uninstrumented 6.204
FPS result as if only division changed. The divide brackets include calls,
timer-read latency, interrupts and task preemption. They are elapsed costs,
not exact CPU cycles. The nominal timer frequency is 4,166,700 Hz; a separate
back-to-back read calibration is retained without subtracting it from results.
The existing 10 ms task-CPU attribution remains available independently.

## Accepted bounded results

| Metric | Profiled original | Profiled exact divide |
| --- | ---: | ---: |
| Host frame availability | 6.0466 FPS | 6.3091 FPS |
| Renderer elapsed | 144.94 ms | 138.08 ms |
| Renderer sampled CPU | 142.38 ms | 135.51 ms |
| BSP/walls | 87.29 ms | 80.40 ms |
| Planes | 40.14 ms | 40.36 ms |
| Sprites | 17.51 ms | 17.31 ms |
| FixedDiv inclusive elapsed/frame | 9.588 ms | 3.669 ms |
| FixedDiv calls/frame | 480.67 | 480.67 |
| Completion observed → HTTP availability | 4.58 ms | 4.84 ms |
| Release gate wait | 2.69 ms | 2.64 ms |
| Release ioctl | 7.62 ms | 7.63 ms |

FPS improves **4.34%**, renderer elapsed falls **4.73% / 6.86 ms**, and inclusive
division brackets fall **61.74% / 5.92 ms**. Individual runs are A1 6.0370,
B1 6.3071, B2 6.3111, A2 6.0562 FPS. The gain repeats in reversed order.
No transport-latency improvement is established: HTTP availability is slightly
slower, and DMA-start-to-HTTP clock bounds overlap (13.60–46.33 vs
17.48–46.89 ms). These are not input-to-browser-paint measurements.

The busiest sites are wall scale (`R_ScaleFromGlobalAngle`, about 204 calls/frame),
the two point-to-distance divisions (about 110 each), and sprite projection/
inverse scale (about 26 each). Plane setup calls FixedDiv only twice per frame.
`division-profile.json` retains every site, including inactive sites, and exact
tick totals. Back-to-back counter reads average about 0.829 μs in both builds.
The improvement is consistent with the BSP/wall timing reduction, but code
layout/cache effects are not separately isolated.

All **2,080 frames / 231 full paired audits** pass. Every corresponding pixel
and palette agrees in all four runs, and every per-frame call-count trace agrees.
The strict image checker passes without adding exceptions. This batch does not
resolve the earlier asynchronous menu-input discrepancy; consumed-frame/tic
instrumentation is still future work. The first 52 card frames retain exactly
the same four known native pixel differences (29260, 29261, 29580, 29581).

There are **66,560 successful on-card differential checks** across the four
runs. Each run passes the three-second held-slot stall, held-frame STOP, full
system/frame/WAD replay, heap drain, 24 frame-tamper and four drain-tamper tests.
Eight additional FDV1 schema mutations are rejected per real capture. Maximum
IRQ gap is **10.810 ms** overall (candidate maximum 10.492 ms). All **1,944**
received HTTP payloads match their captured full frames exactly; the observer
is not a browser paint benchmark and does not claim to receive every frame.

Keep the candidate opt-in. This is fixed-low-detail, one workload and a bounded
session, not broad map/high-detail or long-session qualification. The next
performance step is to qualify the exact divide without per-call profiling and
differential-test overhead; do not claim its uninstrumented FPS before testing.
`first-pair-*` and `a1-*` reports remain explicitly preliminary; final results
are in `comparison.json`, `division-profile.json`, `strict-images.json`,
`pixels-http.json` and `acceptance-summary.json`.

## Reproduce

On the qualified host, build a fresh baseline with:

```sh
python3 game/doom/play/build.py --work /home/mit/doom-div-baseline \
  --pipeline --pingpong --wad-ring --wad-profile --peer-yield \
  --frame-profile --cpu-profile --low-detail --no-fnv --direct-frame \
  --fast-render --fast-columns --fixed-div-profile
```

Build the candidate at a different fresh work path, adding `--fast-fixed-div`.
Do not change detail or other flags between timing runs. The current experiment
uses fixed low detail; runtime F5 quality selection remains a separate option.

```sh
sudo python3 game/doom/play/run.py --work /home/mit/doom-div-baseline \
  --output /home/mit/doom-div-baseline-capture \
  --pipeline --pipeline-test --wad-dma --wad-ring --pingpong \
  --debug-audits --wad-load-test --port 8087 --frames 520 \
  --release-schedule priority
```

`PLAN.md`, `build.sh`, `run.sh` and `accept.py` preserve the actual matched
procedure. The isolated workspace is `/home/mit/i960-fixeddiv-20261016`;
`build` is the profiled original and `build-fast` the profiled candidate.
The builders reused an isolated copy of the accepted column build to avoid
redownloading dependencies; the fresh-work command above is the standalone
reproduction path. Never force-unload a retained exclusive module. Save and
hash-check captures locally before rebooting between sessions.

`verify.sh` runs full system/frame/WAD replays and frame/drain tamper tests.
`game/doom/fixed_div/test_capture.py` independently decodes every real timing
trailer and rejects eight malformed schema variants. `check_frames.py` remains
a strict all-run pixel/palette comparison; `image_report.py` lists every
mismatch instead of masking asynchronous menu-input differences. HTTP receiver
records validate exact binary payloads, not browser paint time.

## Evidence

- `accepted-binaries.sha256`: exact kernels, modules and engine templates.
- `sizing.json`: both admissions remain below 900,000 bytes. Baseline 874,600,
  candidate 874,632; no extra heap allocation. Candidate adds 32 text bytes
  relative to the instrumented baseline. Both retain the byte-identical
  R_PointOnSide O0 object.
- `fixed-sites.json`: generated call-site IDs and source lines. Line numbers
  refer to the transformed pinned sources in the archive, not upstream lines.
- `legacy-divdi3-disassembly.txt`, `fast-divide-disassembly.txt` and
  `ediv-disassembly.txt`: actual target instructions.
- Native logs: two deterministic 52-frame runs per build, identical pixels and
  palette to the prior accepted native baseline, plus 40-frame input/STOP/drain.
- The arithmetic/trailer test logs and unchanged existing-profile tests remain
  alongside the physical captures.

See [implementation](../../game/doom/fixed_div/README.md) for the trailer schema
and [Intel Rx manual](https://datasheets.chipdb.org/Intel/80960/manuals/27273602.PDF)
for the unsigned extended divide and destination-register order.
