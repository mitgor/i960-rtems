# IRQ gap investigation — 2026-10-15

Prior accepted peer-yield captures place the new maximum between
279.879 and 283.215 host seconds, after STOP. Last pre-STOP maximum is 10.669 ms;
final maximum is 59.855 ms. This is not evidence of a gameplay IRQ stall.

The original Worker masks interrupts before the two-worker STOP barrier and
retains that mask across resident_heap_drain. That function checks all remaining
private payload bytes, and shared_drain checks a pinned shared payload before
unpin/ack. The heap's internal timing brackets only measure individual protected
operations, not those outer masked scans.

First candidate retains the original behavior and adds read-only page 3:
magic DRN1, schema 1, nominal 4,166,700 Hz; words 3–4 counter at each worker's
drain entry, 5–6 drain elapsed counts, 7–8 entry RTEMS ticks, 9–10 elapsed RTEMS
ticks, 11–12 completed drain count, 13–63 zero. Counters wrap modulo 32 bits.
The driver permits page 3 only for peer-yield builds. Every page is frozen and
all 64 replies retained in the existing raw control journal. Full replay binds
the independent diagnostic file to that journal, requires one page per snapshot
and both completed drains. Existing full system, heap, RAM, frame and WAD checks
remain unchanged.

The telemetry occupies the existing engine helper code window and mutable
reserve: 146 protected pages, 16 mutable bytes remain. No memory-map, ownership,
protection-capacity or validation relaxation. The bounded results follow.

## Proposed fix and test distinction

The fixed peer-yield path lowers CPU interrupt priority to 20 only after both
workers have crossed the existing STOP arrival barrier. It scans/drains with
timer IRQs enabled, then restores priority 31 before setting done/suspending.
The existing internal heap/reference locks remain. No allocations or new shared
acquisitions start after the barrier. The shared hold remains pinned through its
byte comparison; private buffers remain owned by their worker. The controller
still requires both done flags and all IRQ continuations drained before final
quiescence/reclamation. No idle-task interrupt context is introduced.

Schema 2 identifies interruptible drain. Full replay additionally requires a
maximum IRQ gap below 20 ms across the whole session. This is a test gate, not a
universal hard-real-time guarantee. Elapsed drain time includes preemption; tick
deltas show whether timer service continued. Normal FPS comparison keeps the
engine, scene and workload unchanged. The separate stress fixture changes only
shared workload selection: every cycle has the existing 81,920-byte pin and an
80-tick hold, instead of every 32nd cycle with an eight-tick hold. It preserves
all content checks and makes the rare shutdown state much easier to exercise.
Stress FPS must not be compared to normal workload FPS.

Native validation covers the old acquire/STOP race, barrier-protected shutdown,
preemption of each worker's drain by the other, timer counter wrapping, restoring
priority 31, immutable completed telemetry, corrupt reports and the IRQ ceiling.

## Reproduced cause (masked stress run)

The 100-frame large-buffer stress run reproduced **60.237 ms** maximum IRQ gap.
Worker 1's actual `resident_heap_drain` took **55.997 ms** with **zero elapsed
RTEMS ticks**; worker 0 took 1.288 ms. Live workload IRQ gaps remained near
10.9 ms before shutdown. This matches the prior 59.855 ms end-of-session spike:
the outer priority-31 region hides the shared payload scan from the individual
heap-operation timing brackets. The fix does not remove or shorten validation;
it lets timer interrupts preempt the scan after the arrival barrier. The final
controller's deliberately masked, fully drained terminal phase remains unchanged.

## Fixed stress result

The same large-buffer workload with interruptible drain measured **60.753 ms**
worker-1 elapsed drain and **six advancing timer ticks**. Worker 0 took 2.728 ms.
Maximum observed IRQ gap stayed at **10.495 ms**, versus **60.237 ms** with the
old outer mask. The check itself is not faster: it can now be preempted. The
normal fixed run remains the FPS result: **5.192 FPS**. The two stress runs add
71 / 73 full paired audits; all four runs total **400 frames and 249 audit pairs**.
Each retained the 100-frame test, paired DMA/mailbox comparisons, held-slot
stall/STOP, WAD service, full system/RAM/heap audits and final allocation drain.
Full Linux/Mac replay and 39 mutation rejections per capture cover the original
24 frame, 3 WAD, 8 profile and four added drain mutations. No audit was disabled.

The fixed build additionally compares drain elapsed counts against its RTEMS
tick delta, with a two-tick quantization/interruption allowance. A drain over
20 ms must show tick progress. This catches a long final masked drain even if
no following IRQ sample exists. Old schema-1 captures retain their zero-tick
assertion and are intentionally not labelled latency-qualified. New page data
is required when the admitted kernel symbols contain `peer_drain_report`.

The stress fixture is diagnostic only, not production workload policy. It makes
upload much slower and changes the warm-restart frame boundary. The normal
comparison script correctly refuses its frame-66–68 request-count mismatch;
`frame-analysis.json` retains the raw figures and native comparisons, but those
fixed restart intervals must not be used as a loading speed claim. The first
52 frames still match baseline bytes/palettes with the four existing native
pixel differences. No new Doom rendering divergence was accepted.

IRQ gap is the interval between ISR samples, whose nominal period is 10 ms.
It is not the same as absolute interrupt-entry latency. The separately retained
timer-1 entry-phase field wraps each period and cannot by itself count missed
interrupt periods. `results.json` preserves gap, entry phase, mean period and
sample counts without treating the modulo phase as an unbounded latency proof.
