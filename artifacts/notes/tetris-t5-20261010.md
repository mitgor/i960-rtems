# Persistent-session T5 evidence, 2026-10-10

See [PERSISTENT-SESSION.md](../../docs/loader/PERSISTENT-SESSION.md) for the implementation,
measurements, audit tradeoff and reproduction instructions.

- `evidence.tar.xz`: complete remote captures for conservative `smoke` (3 frames),
  `smoke-optimized` (40), `smoke-fast` (40), `replay` (1,000), `cadence` (400),
  `lifecycle` and repeated `lifecycle-final` (15 cases each). Includes the two
  intermediate module binaries. Extract into a new directory. Captures of OPEN,
  CLOSE and preflight are ordinary files; per-frame data is in `steps.zip`.
- `module/`: exact final Linux 6.8.0-138-generic module and generated sources.
  SHA256 of `dac960session.ko` is
  `3fb2cdda3817101eef34c28b18f00fd4cd6ef756f715ca6dea4e6b5d4579143f`.
- `development-sources/`: generated sources matching the conservative and
  intermediate modules, before the last cache-handshake optimization.
- `target/`: exact T2 i960 payload, Linux native oracle and prepared BIO1 image.
  Payload SHA256 is
  `a889d8081c702ff1dcf9bb51a95d00b0fbcf12c11fbb4ff4d7d51f368cd096af`.
- `source/`: session implementation, test/client scripts and dependencies,
  target source, and documentation snapshot. Generated `module/` is directly
  buildable on the matching Linux kernel; regeneration also uses the existing
  pinned `artifacts/software-loader-20261010/target/runner.bin` in the repository.
- `*-summary.json`: directly readable measurements and lifecycle outcomes.
- `*-validation.json`: independent Mac replay/cadence verification and all 30
  paired restoration captures, including callback table/code/result bytes.
- `native-session-tests.txt`: ASan/UBSan command-fault test output.
- `loadrun-regression-tests.txt`: existing ten-test suite and 424 fault cases.
- `final-host-state.json`: same boot, no DAC960 loader modules, driverless card.

Main replay median 41.12 ms; paced run 20.007 Hz over 400 frames. Final full RAM
restoration and firmware health checks passed. No flash operation or reboot.
Routine frames check all 45,152 payload bytes twice; every 32nd frame checks the
full staging image. CLOSE checks the full response image and full restored image.
This is not a 30-minute interactive test, hardware recovery test, or disk-I/O test.

Replay ZIP entries retain each command transcript, BIO1 response and XOR of the
actually audited region against the original ROM. The original request is in
`progress.jsonl`, and each reconstructed audit has a SHA256. Short audit entries
are 45,152 bytes; they do not claim a fresh read of the remaining staging bytes.
Cadence ZIPs instead retain request/response blocks and kernel transcripts;
oracle preparation and ZIP writing are outside their timed interval.

Native failure tests use a simulated transport. Hardware SIGKILL sweeps kill only
test children at measured delays, allowing in-progress synchronous work to finish
before final-release restoration. They sample phases, not every instruction.
The conservative and intermediate smoke evidence use their earlier audit formats;
the final offline replay validator targets `replay` and `smoke-fast`.
