# AcceleRAID 160 native RTEMS: next ten offline steps

Updated 2026-11-16. Execute these in dependency order without per-step confirmation. Work is limited to saved images, source, local builds, QEMU, and the exploratory i960 model. Do not access `192.168.2.80`, stage or flash a card, or treat a model pass as a hardware boot result. Preserve each prior image and its hashes.

| # | Step | Evidence needed to close it | Owner / state |
| --- | --- | --- | --- |
| 1 | Freeze and repeat the stock `0x2d` request/reply under the existing absent-device model. | Two independent request and reply hashes match; 512-byte fixture and raw logs retained. | Architect / complete: [capture](../artifacts/current/accele160-stock-ioctl2d-20261116/README.md) |
| 2 | Inspect `0x2d` structure and compare stock reply to the controller's saved identifiers and earlier replies. | Offset map identifies known bytes, constants, and unknowns; implementation is explicitly scoped to the exact captured request. | Architect / complete: [descriptor comparison](../artifacts/current/accele160-stock-ioctl2d-20261116/descriptor-comparison.json) |
| 3 | Implement bounded native RTEMS `0x2d` mailbox parsing and reply composition. | Exact request accepted, wrong length/address/opcode rejected; 512-byte reply matches the stock fixture. | `ioctl2d` subagent / complete: [image and direct gates](../artifacts/current/accele160-native-ioctl2d-20261116/README.md) |
| 4 | Cross-build and pack a fifth-reply second-spare image, then run direct i960 gates. | Build receipt, image hash, allowed-region diff, valid and malformed command receipts. | `ioctl2d` subagent / complete: [image and direct gates](../artifacts/current/accele160-native-ioctl2d-20261116/README.md) |
| 5 | Add opt-in QEMU fifth-request support and run the coupled stock x86 ROM plus native i960 gate. | Five native completions; exact `0x2d` payload; ROM exits its mailbox wait or reaches the next observable state. | `emulator_gate` subagent / complete: [coupled gate](../artifacts/current/accele160-native-ioctl2d-coupled-20261116/README.md) |
| 6 | Boot the existing Alpine ISO through the coupled native image. | Serial login or precise failure point, full QEMU/ROM/i960 traces; no fabricated firmware reply. | Architect / complete: [Linux login gate](../artifacts/current/accele160-native-linux-guest-20261116/README.md) |
| 7 | Observe Linux PCI and `myrs` driver state under the virtual card. | Guest evidence of PCI enumeration and driver result; any subsequent commands captured without pretending disks exist. | `emulator_gate` and `ioctl2d` subagents / [Alpine serial probe](../artifacts/current/accele160-native-linux-serial-probe-20261116/README.md) found no `myrs`; a Debian `myrs` guest submitted sixth `0x8e` SET_MEM_MBOX then stalled. [Driver boundary](../artifacts/current/accele160-myrs-guest-20261116/README.md); stock i960 observedly completes `0x8e`; an opt-in stock bridge exposes that completion and the driver advances to `MMBOX_NEW_CMD`. Stock `MMBOX_NEW_CMD` reveals a 64-byte GET_CTLR_INFO ring slot. A [controlled stock replay](../artifacts/current/accele160-mmbox-idb10-investigation-20261116/README.md) supports IDB `0x10` to local bit 4; native `0x8e` and ring DMA/status handling remain pending. |
| 8 | Reduce emulator assumptions around reset, interrupts, ISP no-device scan and MU timing. | List every injected status/vector, compare stock/native runs, and add one discriminating negative check for each changed behavior. | `hardware_audit` and `emulator_gate` subagents / partial: [assumption inventory](hardware/ACCELE160-EMULATOR-ASSUMPTIONS.md), [PCI-readiness negative gate](../artifacts/current/accele160-model-assumption-audit-20261116/readiness-negative.txt), and [ISP source-mask guard](../artifacts/current/accele160-isp-pin-source-guard-20261116/README.md); synthetic ISP status and physical timing remain |
| 9 | Audit the unexplained first-spare pre-beep failure and prepare read-only remote discriminators. | Hypothesis matrix with supporting evidence, missing measurement and safest read-only probe per hypothesis. | `hardware_audit` subagent / complete: [failure audit](hardware/ACCELE160-POST-FAILURE-AUDIT.md) |
| 10 | Integrate reproducible build, replay, recovery and eventual flash decision package. | Exact source/image hashes, one-command offline gates, known limitations, card-specific descriptor checks, recovery and rollback path. A later flash requires its own explicit decision. | Architect / offline gate complete: [aggregate gate](../artifacts/current/accele160-native-offline-gate-20261116/README.md) and [read-only collector](../host/accele160/offline_return/README.md); [programmer recovery package](hardware/ACCELE160-EXTERNAL-PROGRAMMER-RECOVERY.md) prepared; physical profile/restore validation and flash decision remain |

A step closes only on its stated evidence. A failure is recorded with its artifacts and becomes the next bounded investigation; it is not silently converted to a pass. Current work does not raise the physical cold-boot confidence to 80%.
