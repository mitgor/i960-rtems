# AcceleRAID 160: offline work before the remote PC returns

Updated 2026-11-16. Work here uses saved flash images, source, traces, and local emulation. It does not require the card at `192.168.2.80` and does not authorize another flash. The first spare's exact intended native image was verified by an external programmer, yet that card stopped the HP PC before the beep. Disabling Slot 6 option-ROM download did not cure it. The [six-hour offline diagnostic run](ACCELE160-SIX-HOUR-OFFLINE-RUNS.md) has completed two verified second-spare images and a read-only return kit, but neither image is a cold-boot candidate yet.

The critical gap is host-visible controller startup. In the exploratory i960 replay the stock firmware eventually constructs board kind `0x20` and PIRSR `0x0e`; the native RTEMS diagnostic reaches its scheduler `PASS` and parks with no such state or mailbox service. The model's reset selector and some MMIO values are inferred, so replay is evidence of a missing implementation, not proof of the HP hang's cause.

## Gates and limits

1. A clean local build and a QEMU boot improve confidence in the image and host protocol, but QEMU does not emulate this HP BIOS or all i960/80303 reset behavior.
2. The first hardware failure remains unexplained. Do not assign a success percentage from simulation alone or flash the second spare merely because emulator tests pass.
3. Keep per-card descriptor bytes from that card's own verified stock capture. Never substitute another spare's 1 MiB image.
4. Preserve old artifacts. Place new build products and evidence in a new dated directory, with source version, commands, SHA-256, and model assumptions.
5. On the remote's return, begin with read-only measurements. A hardware flash is a distinct later step.
