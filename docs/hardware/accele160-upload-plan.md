# AcceleRAID 160 upload and RTEMS path after the retained-grant proof

Status, 2026-10-17: the new card persistently runs operations 4–6. A fixed 512 KiB stock allocation at `c0710000` was retained between host commands, a reversible 4 KiB host write passed in an odd owned page, and one card-side copy into the first even page passed with destination FNV `0x6121fdc5`. No general image or RTEMS code has run on this board.

BAR0 is an 8 KiB PCI BAR with a 4 KiB Messaging Unit and one translated 4 KiB local-RAM aperture. PIATVR is 8 KiB aligned and the aperture maps `PIATVR + 0x1000`; host MMIO can therefore address only odd 4 KiB pages. A direct copy of an RTEMS image through BAR0 would leave every even page missing. The stock `MEMCOPY` command is a SCSI/device route, not a proven arbitrary local-memory upload. Do not infer a full grant is host-addressable from the successful odd-page test.

The accepted current image preserves operations 1–5 and adds one bounded page-copy operation. Reserve the final odd page of the 512 KiB grant (`grant + 0x7f000`) as a staging page. The other 127 pages are potential payload capacity: 520,192 bytes. The host writes up to 4,096 bytes to the staging page through PIATVR, reads them back, then writes a small control record at a fixed loader address outside the operation-4 owner record. The zero-DMA mailbox contains only operation number, signature and nonce; the stock command engine sees no nonzero SGE or host DMA descriptor. The current card handler validates the owner ID and grant bounds, target page index `0..126`, fixed 4,096-byte length, nonce and FNV checksum, invalidates D-cache before reading PCI-written bytes, and checks the staging checksum **before** copying. It copies 1,024 aligned words to the target and reports a card-computed result. Indexes 0, 1 and 126 passed with valid checksums. A bad staged hash and forbidden index 127 both returned status 2 before copy; the directly readable destination stayed unchanged for the bad hash. The successful runs restored staging, controls, allocator metadata and loader page. A timeout retains the grant and companion; no automatic retry writes over uncertain state.

For admission, the host must keep two same-boot guarded full-flash reads of the exact helper, exact BDF/driver and old-card-unbound checks, a full allocator owner/count snapshot before and after reserve, per-page host readback and card checksum, and a whole-image digest after all pages. A failed checksum, range check or owner check must leave the image unexecutable. The varied-index and rejection gates have now passed on the card. A second live session retained one grant across two page-copy commands, with the one-shot copy companion reloaded between them, and restored all owner/page/staging state afterward. Add a whole-image digest and let the first executable payload be a tiny normally returning function at a fixed grant offset; it should write a nonce-derived result and leave the allocator metadata unchanged. Only after return, cache handoff and full restoration are proven should the RTEMS BSP use the grant.

The 512 KiB grant can hold an archived roughly 315 KiB IPv6 RTEMS image plus limited workspace, but its old DAC960PG binaries contain board-specific addresses, IRQ and DMA assumptions. Port the new board's startup, timer, interrupt and host transport separately. A bounded task/clock/STOP run is the first RTEMS gate, then host-backed IPv4/IPv6 and web service. Doom still needs a different 8 MiB owned arena or an explicit stock-firmware handoff; its current old-card runtime must not be loaded into the 512 KiB pool. Preserve full audits and old-card isolation at each gate.

## Accepted contiguous digest (2026-10-17)

The [op-7 artifact](../../artifacts/current/accele160-digest-20261017/README.md) records a persistent exact firmware image, two same-boot guarded full-flash reads, two contiguous copied pages under one stock owner record, and a card-computed 8 KiB FNV matching the host (`0x3201b5c5`). Bad expected hash and page count 128 each returned stock status 2 with unchanged directly readable target. All three live sessions restored owner metadata, staging, controls, loader page and PIATVR; post-call full-flash reads matched. FNV is a transfer-error check, not a cryptographic authenticity check. The next executable gate is a fixed, normally returning function at the owned grant base, admitted only after full-image digest and explicit I-cache handoff, then full restoration before any RTEMS port.

## Accepted exact leaf from owned RAM (2026-10-17)

The [op-8 artifact](../../artifacts/current/accele160-ownedexec-20261017/README.md) records persistent flash, paired complete reads, an 8 KiB owned upload and whole-image digest, exact 80-byte code admission, I-cache invalidate, normal `callx` at `c0710000`, verified nonce/sum result and complete restoration. Bad digest and modified leaf bytes rejected before call; a second normal session succeeded. The next scale gate is a 77-page upload comparable to the archived 315 KiB RTEMS IPv6 image, then a board-specific relocated task/clock/STOP payload. Do not use the DAC960PG RTEMS binary directly; its addresses, transport and timer assumptions remain board-specific.
