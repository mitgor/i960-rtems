# AcceleRAID 160 upload and RTEMS path after the retained-grant proof

Status, 2026-10-16: the new card persistently runs the exact operation-4/5 firmware. A fixed 512 KiB stock allocation at `c0710000` was retained between two host commands, and a 4 KiB host write/read/restore passed inside its first accessible odd page. No general image or RTEMS code has run on this board.

BAR0 is an 8 KiB PCI BAR with a 4 KiB Messaging Unit and one translated 4 KiB local-RAM aperture. PIATVR is 8 KiB aligned and the aperture maps `PIATVR + 0x1000`; host MMIO can therefore address only odd 4 KiB pages. A direct copy of an RTEMS image through BAR0 would leave every even page missing. The stock `MEMCOPY` command is a SCSI/device route, not a proven arbitrary local-memory upload. Do not infer a full grant is host-addressable from the successful odd-page test.

The next image should preserve operations 1–5 and add one bounded page-copy operation. Reserve the final odd page of the 512 KiB grant (`grant + 0x7f000`) as a staging page. The other 127 pages are potential payload capacity: 520,192 bytes. The host writes up to 4,096 bytes to the staging page through PIATVR, reads them back, then writes a small control record at a fixed loader address outside the operation-4 owner record. The zero-DMA mailbox contains only operation number, signature and nonce; the stock command engine sees no nonzero SGE or host DMA descriptor. The card handler validates the owner ID and grant bounds, target page index `0..126`, byte count `1..4096`, nonce and checksum, invalidates D-cache before reading PCI-written bytes, and checks the staging checksum **before** copying. It copies bounded aligned words to the target and reports a card-computed result. A timeout retains the grant and companion; no automatic retry writes over uncertain state.

For admission, the host must keep two same-boot guarded full-flash reads of the exact helper, exact BDF/driver and old-card-unbound checks, a full allocator owner/count snapshot before and after reserve, per-page host readback and card checksum, and a whole-image digest after all pages. A failed checksum, range check or owner check must leave the image unexecutable. The first live payload should be a tiny normally returning function at a fixed grant offset; it should write a nonce-derived result and leave the allocator metadata unchanged. Only after return, cache handoff and full restoration are proven should the RTEMS BSP use the grant.

The 512 KiB grant can hold an archived roughly 315 KiB IPv6 RTEMS image plus limited workspace, but its old DAC960PG binaries contain board-specific addresses, IRQ and DMA assumptions. Port the new board's startup, timer, interrupt and host transport separately. A bounded task/clock/STOP run is the first RTEMS gate, then host-backed IPv4/IPv6 and web service. Doom still needs a different 8 MiB owned arena or an explicit stock-firmware handoff; its current old-card runtime must not be loaded into the 512 KiB pool. Preserve full audits and old-card isolation at each gate.
