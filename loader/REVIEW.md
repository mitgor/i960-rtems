# Loader implementation review and hand-off

> **2026-10-10 architecture correction:** Intel i960 Rx manual §4.1 forbids
> instruction fetch from internal data RAM (0x000..0x3ff). The hello-at-0x200 /
> GO milestone described below is invalid on hardware. Current C tests check
> software behavior only. See [PROJECT-REVIEW.md](../docs/project/PROJECT-REVIEW.md), item 12.
> Executable payloads need verified external memory; code has not yet been fixed.

Date: 2026-10-10. This records the loader review and implementation for future
Claude Code/Codex sessions. Read [PROTOCOL.md](PROTOCOL.md) before changing the
handshake. The repo's hardware investigations remain relevant; these software
checks do not supersede them.

## Implemented improvements

1. **Restart-safe sequence selection.** Each sender drains a pending transaction,
   derives its sequence from the current acknowledgment, and then increments it.
   The previous `ping` followed by a fresh `load` could falsely accept an old ACK,
   skip SET_ADDR, and write through a null destination. Regression coverage now
   executes the C sender with delayed card consumption.
2. **Actual C tests.** Replaced the independent Python protocol model with a
   compatibility wrapper for native C sender/dispatcher tests. Firmware dispatch
   is an inline function shared by production and tests. Startup and real MMIO
   execution remain outside these tests.
3. **Address and state guards.** Payloads use only aligned words in the 512-byte
   internal-RAM region. Wrong-mode, pre-SET_ADDR, out-of-bounds, and exhausted
   writes are rejected. Invalid SET_ADDR clears any previous pointer. Register
   access uses separate opcodes and excludes protocol mailboxes.
4. **Correct error handling.** Expected status is checked for every command;
   timeouts and rejected GO return failure. Hand-off is distinguished from
   payload execution. File read/close failures are reported and files are closed.
5. **Verified uploads.** Read the entire bounded payload before transmission,
   reject empty/oversized transfers, zero-pad the final word, and read back each
   word. Mismatches or partial uploads return failure. Report original and padded
   sizes separately.
6. **Build/image invariants.** Linker assertions reject writable storage/BSS,
   wrong entry placement, and payload overflow. ELF/binary checks also reject
   unexpected allocated sections, wrong content, and inconsistent flat sizes.
   Stock validation gates the known donor layout and link address before invoking
   the existing image builder. Target maps, disassembly, and undefined-symbol
   reports are generated by `make check`.
7. **Predictable polling.** Two-second monotonic deadlines with polling sleeps
   replace CPU-dependent iteration counts; diagnostics include opcode, argument,
   sequence, and mailbox values.
8. **CLI/device ownership.** Strict numeric parsing and exact argument counts
   precede PCI access. Full PCI BDF selection is preferred; historical BAR0
   selection must resolve to a matching controller. Map Linux sysfs `resource0`,
   validate identity/type/size, reject bound drivers, and serialize loadctl
   processes with an advisory device lock.
9. **Stable hand-off marker.** Keep HANDOFF in OMR0; hello writes its execution
   marker to OMR1. The host can observe the ACK after immediate payload execution.
10. **Build automation/documentation.** Added `make test`, configurable HOSTCC,
    hello's header dependency, quoted/validated STOCK, generated-file ignores,
    updated README, protocol documentation, and Claude Code instruction files.

## Remaining gates and limits

- **No local i960 cross-toolchain; target build has not been performed.** Run
  `make all check` on the Linux toolchain box, inspect map/disassembly, and record
  versions and results here. The larger dispatcher may change register-frame and
  stack usage; verify it fits below `0x200` and has no unexpected helper calls.
- **Startup is unchanged and unverified.** In particular, review fp/sp setup,
  inherited PRCB/register cache, and `flushreg` behavior. Do not assert that shallow
  calls cannot spill just because the source is small. No startup assembly change
  was made without supporting architecture evidence.
- **No card execution or flash operation was performed.** Confirm the MU mapping,
  MMIO commit/ACK ordering, sysfs resource mapping and advisory locking on the
  actual Linux machine, internal RAM instruction fetch, and both bring-up
  milestones. Native tests cannot prove these.
- **DRAM payloads are intentionally rejected.** The previous README's arbitrary
  DRAM upload path is replaced by a bounded no-DRAM implementation. Board timing,
  DRAM base/end, initialization, and support for larger files require verified
  evidence and coordinated range/protocol/linker changes.
- **Ownership is cooperative.** Advisory locks stop other loadctl processes,
  not unrelated tools or driver binding. Keep the controller unbound throughout.
- **Reset during an in-flight operation is not transactional.** Do not assume
  memory writes survived or retry a WRITE blindly. Reset/reinspect, synchronize,
  and reupload from SET_ADDR after an uncertain session. Each separate CLI
  invocation is locked; a sequence of separate load/go invocations is not an
  atomic multi-process session.
- **Firmware donor validation is structural.** It does not prove board
  compatibility or recoverability. Retain the external-programmer backup gate in
  REFLASH.md. No protocol version negotiation/authentication is implemented.
