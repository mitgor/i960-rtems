# Finite DMA chain: STOP while channel 0 is active

The [first 256-byte DMA proof](../dma_transfer/README.md) established a completed transfer. This gate exercised STOP **during** a longer card-initiated transfer without changing flash or touching the old DAC960PG. The Intel 80303 manual says clearing CCR enable suspends DMA rather than aborting it. Accordingly, this image never treats STOP as permission to disable an active channel or release either allocation: it records STOP, lets its finite chain finish, verifies channel inactivity, and only then returns the RTEMS lease.

The accepted image generates 13,000 aligned descriptors inside the owner-tagged 512 KiB card grant at `c0723000..c07888ff`. Each descriptor copies the same 2,048-byte source at `c0789000..c07897ff` to a single pinned, coherent 4 KiB host payload page, for **26,624,000 bytes of PCI writes** per run. The source has `i ^ 0xa6` in its first 256 bytes and `0x5a` afterward; the 4 KiB host payload tail and its two 4 KiB guards must remain unchanged. The card invalidates its data cache every 64 polls before reading the PCI-written STOP sideband. The poll is bounded at 250 hardware ticks within a 300-tick RTEMS lease. On error or uncertain completion, the host runner retains the pin, command modules and stock-owned RAM grant.

On boot `a248da87-dfb9-48e1-981a-6a09094fa3bc`, a fresh read-only DMA inventory showed channel 0 and 2 idle and stock channel 1 occupied. Two **unchanged-image** chain runs then passed. STOP was observed at tick 21 while CSR said channel 0 was active; channel 0 reached the final descriptor and became inactive at tick 48 in each run. DAR was `c07888e0`, NDAR/BCR zero, PADR advanced by 2,048 from each independently pinned bus address, LADR ended at `c0789800`, and DCR remained `7`. Host payload, both guards, allocator owner words, staging, loader page, worker and ISR stacks, timer/vector and stock channel 1 checked before release. HALT completed end to end in 567.635/567.820 ms, including callback and host audits. The 28-tick active window suggests roughly 95 MB/s of repeated PCI writes, but the 10 ms tick resolution and same-page target make that an indicative transport figure, **not** a general DMA or application-throughput benchmark.

Six guarded full 1 MiB flash reads in three pairs around the accepted runs matched the unchanged firmware SHA-256 `1c4995ada54f944265c11f346177708351b4ff5a1003ba232f7e39b6a74b89bd`. The exact image SHA-256 is `5ae10f3c8a16ee67b1f56053473e0627bbf55d5ce6df7143ba55abcf848bc2f4`, kernel SHA-256 `41fb3d2ec4ad3a11cd0e0dcab29a7b01647a9a1dfe286de76ed8979a66348b4e`, and pinned host module SHA-256 `1ef0b6c44c8dceb2c1b820b61ac17a1d3096c6be87dc3978cf2dcb296fe89690`. An independent rebuild was byte-identical. [Exact sources, binaries, captures and negative attempts](../../../artifacts/current/accele160-dma-chain-stop-20261017/README.md) are archived. Replay and ten tamper cases:

```sh
python3 rtems/accele160/dma_chain_stop/verify_live.py artifacts/current/accele160-dma-chain-stop-20261017
python3 rtems/accele160/dma_chain_stop/test_verify_live.py artifacts/current/accele160-dma-chain-stop-20261017
```

The path here took three negative runs before acceptance. The first 3,328,000-byte chain completed before the card observed STOP. The first 26.6 MiB candidate was rejected before DMA because the runner encoded prior DCR `7` instead of the fresh inventory's zero. The next 26.6 MiB chain completed but still saw no active STOP; the DMA loop had not invalidated D-cache when reading the sideband. In each case the strict runner retained resources and a reboot released them. These attempts are historical diagnostics, not accepted DMA lifecycle results.

This proves **STOP arrival during an active, finite DMA chain and release after normal completion**. It does not prove cancellation or drain of hardware that is actually stalled, erroring, or indefinitely active, nor process-death recovery. That remains a separate gate before persistent DMA service or Doom framebuffer integration on this card. No firmware write was issued for any of these tests.
